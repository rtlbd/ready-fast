# system-monitor

🌐 [English](../../en/scripts/system-monitor.md) | **বাংলা**

[← ডকুমেন্টেশনের মূল পাতা](../README.md)

## 1. পরিচিতি

`system-monitor` স্ক্রিপ্টটি কয়েক সেকেন্ডের মধ্যে আপনার সার্ভারের সার্বিক অবস্থার একটি রিপোর্ট দেখায়: uptime, CPU load, memory, ডিস্কের জায়গা, ব্যর্থ হওয়া সার্ভিস এবং সবচেয়ে ব্যস্ত process-গুলো। এটি সংখ্যাগুলোকে সতর্কতার সীমার (threshold) সাথে মিলিয়ে দেখে এবং কোনো কিছুতে নজর দেওয়া দরকার হলে স্পষ্টভাবে জানিয়ে দেয়।

স্ক্রিপ্টটি শুধু তথ্য পড়ে। এটি কিছু ইনস্টল করে না, পেছনে কোনো সার্ভিস চালায় না এবং পুরোনো তথ্য জমিয়ে রাখে না। সতর্কবার্তা পাওয়া গেছে কি না তা এর exit status থেকে বোঝা যায়, তাই এটি cron থেকেও ব্যবহার করা যায়। নির্দিষ্ট সময় পরপর চালানোর নিয়ম এবং সংখ্যাগুলো বোঝার জন্য [মনিটরিং](../monitoring.md) গাইডটি দেখুন।

## 2. কী কাজ করে

- Hostname, kernel-এর ভার্সন এবং সার্ভার কতক্ষণ ধরে চালু আছে তা দেখায়।
- CPU core-এর সংখ্যা এবং শেষ 1, 5 ও 15 মিনিটের load average দেখায়।
- কতটুকু memory ও swap ব্যবহার হচ্ছে তা দেখায়।
- প্রতিটি local filesystem কতটা ভরে গেছে তা দেখায়।
- "failed" অবস্থায় থাকা systemd সার্ভিসগুলোর তালিকা দেখায়।
- সবচেয়ে বেশি CPU ব্যবহার করছে এমন পাঁচটি process-এর তালিকা দেখায়।
- প্রতিটি সমস্যার জন্য একটি `WARNING:` লাইন এবং সবশেষে একটি ফলাফলের লাইন দেখায়।

যেসব ক্ষেত্রে সতর্কবার্তা দেওয়া হয়:

| পরীক্ষা | সতর্কবার্তার শর্ত |
| --- | --- |
| CPU load | 1 মিনিটের load average CPU core-এর সংখ্যার চেয়ে বেশি। |
| Memory | Memory-র ব্যবহার `--mem-warn` সীমায় পৌঁছেছে (ডিফল্ট 90%)। |
| ডিস্ক | কোনো filesystem `--disk-warn` সীমায় পৌঁছেছে (ডিফল্ট 85%)। |
| সার্ভিস | অন্তত একটি systemd unit "failed" অবস্থায় আছে। |

## 3. সমর্থিত অপারেটিং সিস্টেম

| ডিস্ট্রিবিউশন | ভার্সন |
| --- | --- |
| Ubuntu | 22.04, 24.04, 26.04 |
| Debian | 12, 13 |

এই স্ক্রিপ্টটি অপারেটিং সিস্টেম যাচাই করে না। অন্য Linux ডিস্ট্রিবিউশনেও এটি কাজ করার কথা, তবে পরীক্ষা করা হয়েছে শুধু টেবিলে উল্লেখ করা সিস্টেমগুলোতে। বিস্তারিত: [সমর্থিত অপারেটিং সিস্টেম](../supported-os.md)।

## 4. যা যা প্রয়োজন

- Root permission: **লাগে না**।
- প্রতিটি সাধারণ সার্ভারে থাকা প্রচলিত টুল: `df`, `nproc`, `awk` এবং `ps` (`procps` প্যাকেজের)।
- ready-fast ইনস্টল করা থাকতে হবে ([ইনস্টলেশন](../installation.md) দেখুন)।

## 5. ইনস্টলেশন কমান্ড

ডিফল্ট সীমা দিয়ে রিপোর্ট:

```bash
ready-fast run system-monitor
```

আরও আগে সতর্ক করবে এমন রিপোর্ট; ডিস্ক 70% এবং memory 80% ব্যবহার হলেই:

```bash
ready-fast run system-monitor --disk-warn 70 --mem-warn 80
```

## 6. ধাপে ধাপে ব্যাখ্যা

**System.** Hostname নেওয়া হয় `hostname` থেকে, kernel-এর ভার্সন `uname -r` থেকে এবং uptime `/proc/uptime` থেকে।

**CPU load.** Core-এর সংখ্যা আসে `nproc` থেকে এবং load average আসে `/proc/loadavg` থেকে। Load average হলো গড়ে কতগুলো process চলছে অথবা CPU-র জন্য অপেক্ষা করছে তার হিসাব। সহজ নিয়ম হলো: load যদি core-এর সংখ্যার চেয়ে বেশি হয়ে থেকেই যায়, তাহলে সার্ভারের ওপর তার সামর্থ্যের চেয়ে বেশি কাজের চাপ পড়ছে।

**Memory.** স্ক্রিপ্টটি `/proc/meminfo` থেকে `MemTotal` ও `MemAvailable` পড়ে এবং মোট থেকে available বাদ দিয়ে ব্যবহৃত memory হিসাব করে। Linux যে memory ডিস্ক cache হিসেবে ব্যবহার করে এবং যেকোনো সময় ছেড়ে দিতে পারে, সেটিও "available"-এর মধ্যে ধরা থাকে; তাই অন্য টুলের "free" কলামের চেয়ে এই সংখ্যাটি বেশি অর্থবহ।

**ডিস্কের ব্যবহার।**

```bash
df -P -l -x tmpfs -x devtmpfs -x squashfs -x efivarfs
```

`-P` আউটপুটের ফরম্যাট স্থির রাখে, `-l` তালিকাটি local filesystem-এর মধ্যে সীমিত রাখে, আর প্রতিটি `-x` এমন এক ধরনের virtual filesystem লুকিয়ে রাখে যা আসল ডিস্ক নয়। `Capacity` কলামটি সীমার সাথে তুলনা করা হয়।

**ব্যর্থ সার্ভিস।**

```bash
systemctl --failed --no-legend --plain
```

systemd যেসব unit চালু করতে চেয়েছিল কিন্তু error দিয়ে শেষ হয়েছে, এই কমান্ড সেগুলোর তালিকা দেয়। systemd চালু না থাকলে (যেমন কোনো container-এর ভেতরে) এই পরীক্ষাটি বাদ দেওয়া হয়।

**সবচেয়ে ব্যস্ত process।**

```bash
ps -eo pid,comm,%cpu,%mem --sort=-%cpu
```

শুধু প্রথম পাঁচটি process দেখানো হয়।

**ফলাফল।** কোনো পরীক্ষায় সতর্কবার্তা না এলে স্ক্রিপ্টটি `Result: no warnings.` দেখিয়ে exit status 0 দিয়ে শেষ হয়। অন্যথায় সতর্কবার্তার সংখ্যা দেখিয়ে exit status 1 দিয়ে শেষ হয়।

## 7. কমান্ড অপশন

| অপশন | অর্থ |
| --- | --- |
| `--disk-warn <percent>` | ডিস্ক ব্যবহারের সতর্কতার সীমা; 1 থেকে 100-এর মধ্যে একটি সংখ্যা। ডিফল্ট: 85। |
| `--mem-warn <percent>` | Memory ব্যবহারের সতর্কতার সীমা; 1 থেকে 100-এর মধ্যে একটি সংখ্যা। ডিফল্ট: 90। |
| `--help` | সাহায্য-বার্তা দেখিয়ে বের হয়ে যায়। |

Exit status: 0 মানে কোনো সতর্কবার্তা নেই, 1 মানে অন্তত একটি সতর্কবার্তা আছে, 2 মানে অপশন ভুল দেওয়া হয়েছে।

## 9. নিরাপত্তা বিষয়ক সতর্কতা

- স্ক্রিপ্টটি শুধু তথ্য পড়ে এবং এর জন্য root permission লাগে না।
- রিপোর্টে process-এর নাম, hostname ও ডিস্কের বিন্যাস দেখা যায়। পাবলিকলি শেয়ার করার আগে একবার দেখে নিন।
- এটি একটি দ্রুত পরীক্ষা মাত্র, পূর্ণাঙ্গ monitoring system নয়। এটি alert পাঠায় না, সার্ভারকে সারাক্ষণ নজরে রাখে না এবং Prometheus, Netdata কিংবা আপনার hosting provider-এর monitoring-এর বিকল্পও নয়।

## 10. সিস্টেমে যেসব পরিবর্তন হয়

কোনো পরিবর্তন হয় না। কোনো ফাইল লেখা হয় না, কোনো প্যাকেজ ইনস্টল হয় না, কোনো সেটিং বদলায় না।

## 11. আগের অবস্থায় ফিরে যাওয়া (Rollback)

ফিরিয়ে নেওয়ার মতো কিছু নেই, কারণ স্ক্রিপ্টটি সিস্টেমে কোনো পরিবর্তন করে না। cron দিয়ে এটি নির্দিষ্ট সময়ে চালানোর ব্যবস্থা করে থাকলে আপনার crontab থেকে সেই লাইনটি মুছে দিন; বিস্তারিত [মনিটরিং](../monitoring.md) গাইডে আছে।

## 12. সমস্যা সমাধান

| সমস্যা | কারণ ও সমাধান |
| --- | --- |
| দেখে কোনো সমস্যা মনে হচ্ছে না, অথচ স্ক্রিপ্টটি exit status 1 দিয়ে শেষ হচ্ছে | অন্তত একটি `WARNING:` লাইন দেখানো হয়েছে। রিপোর্টটি ওপর থেকে পড়ুন; সতর্কবার্তাটি তার নিজের অংশেই আছে। |
| যে filesystem সবসময়ই ভরা থাকে (যেমন কোনো read-only image), সেটির জন্য প্রতিবারই সতর্কবার্তা আসছে | `--disk-warn` দিয়ে সীমাটি বাড়িয়ে দিন। আলাদা করে কোনো একটি filesystem বাদ দেওয়ার সুবিধা নেই। |
| Memory-র ব্যবহার `top` বা `free`-এর চেয়ে কম দেখাচ্ছে | যে memory যেকোনো সময় ছেড়ে দেওয়া যায় (ডিস্ক cache), স্ক্রিপ্টটি সেটিকে available হিসেবে ধরে। এটি ইচ্ছাকৃত। |
| `(systemd is not running; skipped)` | মেশিনটি একটি container অথবা এটি systemd ব্যবহার করে না, তাই ব্যর্থ সার্ভিসের তালিকা দেখানো যায় না। |
| `(the 'ps' command is missing; install the procps package)` | `sudo apt-get install -y procps` দিয়ে ইনস্টল করুন। |
| `Invalid --disk-warn value` অথবা `Invalid --mem-warn value` | সীমাটি 1 থেকে 100-এর মধ্যে একটি পূর্ণসংখ্যা হতে হবে, `%` চিহ্ন ছাড়া। |

সাধারণ সমস্যাগুলোর সমাধান পাবেন [সমস্যা সমাধান](../troubleshooting.md) পাতায়।
