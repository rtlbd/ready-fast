**এক কমান্ডেই সার্ভার প্রস্তুত!**

Linux Server Setup, Docker, Networking, Security, Monitoring এবং DevOps Automation-এর জন্য একটি Ready-to-Run Toolkit.

ready-fast-এ স্বাগতম! এটি যত্ন নিয়ে লেখা কিছু shell script-এর ছোট একটি সংগ্রহ, যেগুলো চালানোর জন্য আছে একটিমাত্র সহজ কমান্ড। প্রতিটি স্ক্রিপ্ট Ubuntu বা Debian সার্ভারে একটি নির্দিষ্ট কাজ করে, কী করতে যাচ্ছে তা আগে বুঝিয়ে বলে এবং কোনো কিছু বদলানোর আগে আপনাকে পুরো প্রক্রিয়াটি দেখে নেওয়ার সুযোগ দেয়।

## এটি কাদের জন্য

- যাঁরা Linux শিখছেন এবং নিরাপদ, ব্যাখ্যাসহ কমান্ড দেখতে চান।
- যাঁদের VPS বা Dedicated Server আছে এবং দ্রুত একটি নিরাপদ প্রাথমিক সেটআপ চান।
- Web developer, যাঁদের দশটি টিউটোরিয়াল না ঘেঁটেই Docker ও firewall দরকার।
- System administrator, network administrator ও DevOps engineer, যাঁরা বারবার একইভাবে করা যায় এবং যাচাই করে দেখা যায় এমন ধাপ চান।

## যে নিরাপত্তা-নিয়মগুলো প্রতিটি স্ক্রিপ্ট মেনে চলে

- **আগে দেখে নিন।** কোনো কিছু বদলায় এমন প্রতিটি স্ক্রিপ্ট `--dry-run` গ্রহণ করে; এতে প্রতিটি ধাপ দেখানো হয়, কিন্তু কিছুই বদলায় না।
- **বদলানোর আগে জিজ্ঞেস করা।** সিস্টেমের সেটিং বদলায় বা ফাইল overwrite করে এমন স্ক্রিপ্টগুলো একটি সারসংক্ষেপ দেখিয়ে আপনার `y`-এর জন্য অপেক্ষা করে। টার্মিনাল না থাকলে এগুলো থেমে যায়, যদি না আপনি `--yes` দেন।
- **অচেনা সিস্টেমে কাজ না করা।** সফটওয়্যার ইনস্টল করে বা সিস্টেমের সেটিং বদলায় এমন স্ক্রিপ্টগুলো অসমর্থিত অপারেটিং সিস্টেমে থেমে যায়।
- **Root কখন লাগবে তা জানিয়ে দেওয়া।** `sudo` লাগবে কি না, প্রতিটি ডকুমেন্টে তা স্পষ্ট করে লেখা আছে।
- **ফিরে যাওয়ার পথ রাখা।** প্রতিটি ডকুমেন্টে আগের অবস্থায় ফিরে যাওয়ার নির্দেশনা আছে। কোনো স্ক্রিপ্ট যে ফাইল বদলায়, তার একটি কপি আগে `/var/backups/ready-fast`-এ রেখে দেয়।
- **কোনো চমক নেই।** কোনো স্ক্রিপ্ট ব্যবহারের তথ্য কোথাও পাঠায় না। ইন্টারনেটে শুধু সেই সংযোগগুলোই হয়, যেগুলোর কথা প্রতিটি ডকুমেন্টে লেখা আছে।

## সমর্থিত সিস্টেম

Ubuntu 22.04, 24.04 ও 26.04 এবং Debian 12 ও 13; `amd64` ও `arm64` architecture-এ। বিস্তারিত আছে [সমর্থিত অপারেটিং সিস্টেম](supported-os.md) পাতায়।

## দুই ভাষার ডকুমেন্টেশন একই রকম রাখা

এই ডকুমেন্টেশন ইংরেজি ও বাংলা দুই ভাষাতেই আছে, এবং দুটিতেই সবসময় একই আচরণের বর্ণনা থাকতে হবে। যাঁরা অবদান রাখবেন, তাঁদের জন্য নিয়মগুলো হলো:

- কোনো স্ক্রিপ্ট বদলালে একই পরিবর্তনের সাথে `docs/en/scripts/` ও `docs/bn/scripts/` দুই জায়গাতেই তার ডকুমেন্ট হালনাগাদ করুন।
- কোনো CLI কমান্ড বা অপশন বদলালে দুই ভাষার `commands.md` হালনাগাদ করুন।
- নতুন কোনো ফিচার বা স্ক্রিপ্ট যোগ হলে merge করার আগেই দুই ভাষায় তার ডকুমেন্ট লিখুন।
- কমান্ড, প্যাকেজের নাম, ফাইলের path, environment variable, configuration key বা প্রোগ্রামের আউটপুট কখনো অনুবাদ করবেন না। শুধু এগুলোর আশপাশের ব্যাখ্যাটুকু অনুবাদ করুন।

এই নিয়মগুলো স্বয়ংক্রিয়ভাবে যাচাই করা হয়। প্রতিটি commit-এর আগে পরীক্ষাটি চালিয়ে নিন:

```bash
python3 tools/validate-docs.py
```

একই পরীক্ষা প্রতিটি push ও pull request-এ GitHub Actions-এ চলে। কোনো অনুবাদ বাদ পড়লে, দুই ভাষার code block আলাদা হলে, কোনো link ভাঙা থাকলে অথবা ডকুমেন্টে লেখা কোনো কমান্ড বা অপশনের অস্তিত্ব না থাকলে পরীক্ষাটি ব্যর্থ হয়।
