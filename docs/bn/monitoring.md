# মনিটরিং

🌐 [English](../en/monitoring.md) | **বাংলা**

[← ডকুমেন্টেশনের মূল পাতা](README.md)

সার্ভারের বেশির ভাগ সমস্যা বড় বিপর্যয়ে রূপ নেওয়ার আগেই জানান দেয়: ডিস্ক ধীরে ধীরে ভরে যায়, memory কমে আসে, রিবুটের পর কোনো সার্ভিস চালু হতে ব্যর্থ হয়। এই গাইডে দেখানো হয়েছে কীভাবে ready-fast দিয়ে সার্ভারের অবস্থা পরীক্ষা করবেন, সংখ্যাগুলো কীভাবে বুঝবেন এবং পরীক্ষাটি কীভাবে নিজে থেকে চলার ব্যবস্থা করবেন।

এই গাইডের পেছনের স্ক্রিপ্টটির বিবরণ আছে [system-monitor](scripts/system-monitor.md) পাতায়। এটি শুধু তথ্য পড়ে এবং এর জন্য root permission লাগে না।

## সার্ভারের অবস্থা পরীক্ষা করুন

```bash
ready-fast run system-monitor
```

- Root permission: লাগবে না।
- ঝুঁকি: নেই। কিছুই ইনস্টল হয় না বা বদলায় না।

রিপোর্টটি এই দুটি লাইনের যেকোনো একটি দিয়ে শেষ হয়:

```text
[OK] Result: no warnings.
```

```text
[WARN] Result: 1 warning(s).
```

সতর্কবার্তা থাকলে প্রতিটি সতর্কবার্তা তার নিজের অংশের ভেতরে `WARNING:` দিয়ে শুরু হওয়া একটি লাইন হিসেবে দেখা যায়।

## সংখ্যাগুলো কীভাবে বুঝবেন

### CPU load

Load average থেকে বোঝা যায় গড়ে কতগুলো process চলছিল অথবা CPU-র জন্য অপেক্ষা করছিল। তিনটি সংখ্যা দেখানো হয়: শেষ 1, 5 ও 15 মিনিটের।

Load-কে CPU core-এর সংখ্যার সাথে তুলনা করুন। 2 core-এর সার্ভারে load 2.00 মানে CPU পুরোপুরি ব্যস্ত। Load যদি core-এর সংখ্যার চেয়ে স্পষ্টভাবে বেশি হয়ে থেকেই যায়, তাহলে বুঝতে হবে কাজ জমে যাচ্ছে। অল্প সময়ের জন্য বেড়ে যাওয়া স্বাভাবিক; কিন্তু 15 মিনিটের মান বেশি হলে সেটি সত্যিই অতিরিক্ত চাপের লক্ষণ।

করণীয়: কোন প্রোগ্রামটি দায়ী তা জানতে "Top processes by CPU" অংশটি দেখুন।

### Memory

রিপোর্টে ব্যবহৃত memory দেখানো হয় "মোট থেকে available বাদ দিয়ে"। Linux খালি memory-কে ফাইলের cache হিসেবে কাজে লাগায় এবং প্রোগ্রামের দরকার পড়ামাত্র তা ফিরিয়ে দেয়; তাই পুরোপুরি সুস্থ একটি সার্ভারকেও অন্য টুলে "ভরা" মনে হতে পারে। এই রিপোর্টের সংখ্যায় বিষয়টি আগে থেকেই হিসাবে ধরা আছে।

Memory দীর্ঘ সময় ধরে সীমার ওপরে থাকলে করণীয়: কোন প্রোগ্রাম সবচেয়ে বেশি ব্যবহার করছে খুঁজে বের করুন, সার্ভারে চলা কাজ কমান, অথবা বেশি memory-র কোনো প্ল্যানে চলে যান।

### Swap

Swap হলো ডিস্কের এমন জায়গা, যা সিস্টেম জরুরি অবস্থায় memory হিসেবে ব্যবহার করে। অনেক VPS-এ swap থাকেই না ("not configured"); তাতে কোনো সমস্যা নেই। Swap থাকলে এবং সেটি খুব বেশি ব্যবহার হলে বুঝতে হবে সার্ভারে আসল memory-র ঘাটতি আছে; তখন সার্ভার ধীর মনে হবে।

### ডিস্কের ব্যবহার

প্রতিটি লাইন একটি filesystem; সাথে তার আকার এবং কতটা ভরেছে তা দেখানো হয়। ডিস্ক ভরে যাওয়া সার্ভার বিকল হওয়ার সবচেয়ে প্রচলিত কারণগুলোর একটি: database থেমে যায়, লগইন ব্যর্থ হয়, আপডেট ভেঙে পড়ে।

করণীয়: কোন ডিরেক্টরিগুলো সবচেয়ে বেশি জায়গা নিচ্ছে খুঁজে বের করুন। যেমন `/var`-এর জন্য:

```bash
sudo du -xh --max-depth=1 /var | sort -h
```

`du` প্রতিটি ডিরেক্টরির আকার যোগ করে দেখায়, `-x` একটি filesystem-এর মধ্যেই সীমিত থাকে, `--max-depth=1` শুধু প্রথম স্তরটি দেখায়, আর `sort -h` সবচেয়ে বড়টিকে সবার নিচে রাখে। সাধারণত দায়ী থাকে পুরোনো log ফাইল, প্যাকেজের cache এবং Docker image (দেখুন [Docker](docker.md))।

### ব্যর্থ সার্ভিস

যেসব সার্ভিস systemd চালু করতে পারেনি অথবা যেগুলো crash করেছে। কোনো সার্ভিস কেন ব্যর্থ হয়েছে তা জানতে (এখানে উদাহরণ হিসেবে `nginx`):

```bash
systemctl status nginx
journalctl -u nginx --no-pager -n 50
```

প্রথম লাইনটি বর্তমান অবস্থা এবং log-এর শেষ কয়েকটি লাইন দেখায়। দ্বিতীয়টি সার্ভিসটির log-এর শেষ 50 লাইন দেখায়।

### সবচেয়ে ব্যস্ত process

এই মুহূর্তে সবচেয়ে বেশি CPU ব্যবহার করছে এমন পাঁচটি process; সাথে প্রতিটি কতটুকু CPU ও memory নিচ্ছে তা-ও দেখানো হয়।

## নিজের মতো সীমা ঠিক করুন

ডিফল্ট সীমা হলো ডিস্ক ব্যবহারের জন্য 85% এবং memory ব্যবহারের জন্য 90%। আরও আগে সতর্কবার্তা পেতে চাইলে:

```bash
ready-fast run system-monitor --disk-warn 70 --mem-warn 80
```

## ফলাফলটি automation-এ ব্যবহার করুন

কোনো সতর্কবার্তা না থাকলে স্ক্রিপ্টটি exit status 0 দিয়ে শেষ হয়, আর অন্তত একটি থাকলে 1 দিয়ে। অন্য প্রোগ্রাম এর ওপর ভিত্তি করে ব্যবস্থা নিতে পারে। একটি সহজ উদাহরণ:

```bash
ready-fast run system-monitor || echo "The server needs attention"
```

`||`-এর পরের লেখাটি শুধু তখনই দেখানো হয়, যখন পরীক্ষায় কোনো সতর্কবার্তা আসে।

## cron দিয়ে পরীক্ষাটি নিয়মিত চালান

cron হলো Linux-এর প্রচলিত সার্ভিস, যা নির্দিষ্ট সময়সূচি অনুযায়ী কমান্ড চালায়। root ব্যবহারকারীর সময়সূচিটি খুলুন:

```bash
sudo crontab -e
```

একদম শেষে এই লাইনটি যোগ করুন, তারপর save করে editor বন্ধ করুন:

```cron
*/15 * * * * /usr/local/bin/ready-fast run system-monitor >> /var/log/ready-fast-monitor.log 2>&1
```

- `*/15 * * * *` মানে "প্রতি 15 মিনিট পরপর"।
- পুরো path `/usr/local/bin/ready-fast` ব্যবহার করা হয়েছে, কারণ cron অল্প কয়েকটি ডিরেক্টরিই চেনে।
- `>> /var/log/ready-fast-monitor.log` প্রতিটি রিপোর্ট একটি log ফাইলের শেষে যোগ করে, আর `2>&1` দিলে error বার্তাগুলোও তাতে যায়।
- ঝুঁকি: প্রতিবার চলার সাথে সাথে log ফাইলটি বড় হতে থাকে; এই বিরতিতে দিনে মোটামুটি 150 KB করে। মাঝে মাঝে এটি মুছে ফেলুন অথবা ছোট করে নিন।

সর্বশেষ রিপোর্টটি পড়ুন, অথবা log-এ সতর্কবার্তা খুঁজে দেখুন:

```bash
sudo tail -n 40 /var/log/ready-fast-monitor.log
sudo grep WARNING /var/log/ready-fast-monitor.log
```

সময়সূচিটি বন্ধ করতে আবার `sudo crontab -e` চালিয়ে লাইনটি মুছে দিন। Log সরাতে চাইলে `/var/log/ready-fast-monitor.log` মুছে ফেলুন।

## এই পদ্ধতির সীমাবদ্ধতা

`system-monitor` একটি দ্রুত পরীক্ষা মাত্র, পূর্ণাঙ্গ monitoring system নয়:

- এটি e-mail, SMS বা chat বার্তা পাঠায় না।
- এটি পুরোনো তথ্য জমিয়ে রাখে না এবং graph আঁকে না।
- সার্ভার বন্ধ হয়ে গেলে এটি তা জানাতে পারে না, কারণ এটি ওই সার্ভারেই চলে।

গুরুত্বপূর্ণ production সার্ভারের জন্য এমন একটি বাইরের সার্ভিসও ব্যবহার করুন, যা বাইরে থেকে পরীক্ষা করে আপনার ওয়েবসাইট সাড়া দিচ্ছে কি না; পাশাপাশি পূর্ণাঙ্গ কোনো monitoring টুলের কথাও ভাবুন। শুরু করার জন্য আপনার hosting provider-এর monitoring পাতাটি বেশ কাজের।

## আরও সাহায্য

স্ক্রিপ্টটির সমস্যাগুলোর তালিকা আছে [system-monitor](scripts/system-monitor.md) পাতায়। সাধারণ সাহায্য পাবেন [সমস্যা সমাধান](troubleshooting.md) পাতায়।
