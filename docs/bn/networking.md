# নেটওয়ার্কিং

🌐 [English](../en/networking.md) | **বাংলা**

[← ডকুমেন্টেশনের মূল পাতা](README.md)

একটি সার্ভারকে সুরক্ষিত করা বা তার সমস্যা সারানোর আগে জানা দরকার সেটি কীভাবে সংযুক্ত: তার কোন কোন address আছে, সেটি কীভাবে ইন্টারনেটে পৌঁছায় এবং কোন কোন প্রোগ্রাম সংযোগের অপেক্ষায় আছে। এই গাইডে দেখানো হয়েছে কীভাবে ready-fast দিয়ে এই তথ্যগুলো পাবেন এবং কীভাবে সেগুলো পড়বেন।

ready-fast নেটওয়ার্কের শুধু রিপোর্ট দেয়। এটি কখনো IP address, route বা DNS সেটিং বদলায় না। এই গাইডের পেছনের স্ক্রিপ্টটির বিবরণ আছে [network-info](scripts/network-info.md) পাতায়।

## রিপোর্ট দেখুন

```bash
ready-fast run network-info
```

- Root permission: লাগবে না।
- ঝুঁকি: নেই। স্ক্রিপ্টটি শুধু তথ্য পড়ে।

`sudo` দিয়ে চালালে port-এর তালিকায় এটাও দেখা যায় যে কোন port কোন প্রোগ্রামের:

```bash
sudo ready-fast run network-info
```

Public IP address ও সংযোগ পরীক্ষাসহ দেখতে:

```bash
ready-fast run network-info --public-ip --check
```

`--public-ip` বাইরের সার্ভিস `api.ipify.org`-কে জিজ্ঞেস করে, আর `--check` সংযোগ করে `example.com`-এর সাথে। এই অপশনগুলো না দিলে আপনার সার্ভার থেকে বাইরে কোনো সংযোগ যায় না।

## রিপোর্ট কীভাবে পড়বেন

### Hostname

সার্ভার নিজেকে যে নামে চেনে। এটি শুধুই একটি পরিচয়-চিহ্ন; নামটি বদলালে সার্ভারে পৌঁছানোর পথ বদলায় না।

### IP address

প্রতিটি লাইন একটি করে network interface:

```text
lo               UNKNOWN        127.0.0.1/8 ::1/128
eth0             UP             203.0.113.10/24
docker0          DOWN           172.17.0.1/16
```

- `lo` হলো loopback interface। `127.0.0.1` address-টির অর্থ সবসময়ই "এই মেশিনটি নিজে"।
- `eth0` (অনেক সার্ভারে `ens3`, `enp1s0` বা এ ধরনের নাম) হলো আসল network card। `UP` মানে এটি সংযুক্ত আছে।
- Docker ইনস্টল থাকলে `docker0` দেখা যায়। কোনো container না চললে এটি `DOWN` থাকে।
- যেসব address `10.`, `192.168.` অথবা `172.16.` থেকে `172.31.` দিয়ে শুরু, সেগুলো private address। এগুলো শুধু local network-এর ভেতরে কাজ করে। আপনার সার্ভারে শুধু private address দেখা গেলে বুঝতে হবে এর public address-টি provider-এর router সামলাচ্ছে; `--public-ip` দিলে সেটি দেখা যায়।

### Default route

```text
default via 203.0.113.1 dev eth0
```

`via`-এর পরের address-টি হলো gateway: যে router-এর কাছে সার্ভার তার নিজের network-এর বাইরের সবকিছু পাঠায়। এখানে কোনো লাইন না থাকা মানে ইন্টারনেট সংযোগ নেই।

### DNS server

যে server-গুলো `example.com`-এর মতো নামকে IP address-এ রূপান্তর করে। Ubuntu-তে প্রায়ই `127.0.0.53` দেখা যায়। এটি একটি local সহায়ক সার্ভিস (`systemd-resolved`); আসল server-গুলো দেখা যায় `resolvectl status` দিয়ে।

### Listening port

```text
Netid State  Recv-Q Send-Q Local Address:Port Peer Address:Port
tcp   LISTEN 0      128          0.0.0.0:22        0.0.0.0:*
tcp   LISTEN 0      511        127.0.0.1:3306      0.0.0.0:*
```

প্রতিটি লাইন এমন একটি প্রোগ্রাম, যা সংযোগের অপেক্ষায় আছে। সবচেয়ে গুরুত্বপূর্ণ কলামটি হলো `Local Address:Port`:

- `0.0.0.0:22` অথবা `[::]:22` মানে প্রোগ্রামটি **সব জায়গা থেকে** সংযোগ গ্রহণ করে, যদি না কোনো firewall তা আটকায়।
- `127.0.0.1:3306` মানে প্রোগ্রামটি **শুধু সার্ভারের নিজের ভেতর থেকে** সংযোগ গ্রহণ করে। Database-এর জন্য এটিই নিরাপদ সেটিং।

কয়েকটি সুপরিচিত port:

| Port | সাধারণত যে সার্ভিস |
| --- | --- |
| 22 | SSH |
| 80 | HTTP (ওয়েবসাইট) |
| 443 | HTTPS (এনক্রিপ্ট করা ওয়েবসাইট) |
| 3306 | MySQL অথবা MariaDB |
| 5432 | PostgreSQL |
| 6379 | Redis |
| 27017 | MongoDB |

কোনো database-এর port যদি `0.0.0.0` দিয়ে তালিকায় থাকে, তাহলে ইন্টারনেটের যে কেউ সেটিতে সংযোগের চেষ্টা করতে পারে। Database-এর কনফিগারেশন বদলে সেটিকে `127.0.0.1`-এ listen করান, অথবা firewall দিয়ে port-টি বন্ধ করুন।

## প্রচলিত কিছু প্রশ্নের উত্তর

**আমার সার্ভারের public IP address কত?**

```bash
ready-fast run network-info --public-ip
```

**ইন্টারনেট সংযোগ কাজ করছে কি?**

```bash
ready-fast run network-info --check
```

পরীক্ষার দুটি লাইনের শেষেই `OK` থাকার কথা। DNS পরীক্ষা ব্যর্থ হলে নাম resolve হচ্ছে না; আর শুধু HTTPS পরীক্ষা ব্যর্থ হলে বাইরের দিকে সংযোগ কোথাও আটকে যাচ্ছে।

**কোনো port কোন প্রোগ্রাম ব্যবহার করছে?** রিপোর্টটি `sudo` দিয়ে চালান এবং "Listening ports" অংশে লাইনের শেষ দিকটা দেখুন। `users:(("nginx",pid=812,fd=6))` লেখাটির অর্থ হলো প্রোগ্রামটি `nginx` এবং তার process নম্বর 812।

**বাইরে থেকে কেউ আমার সার্ভিসে পৌঁছাতে পারছে না কেন?** ক্রম অনুযায়ী এই তিনটি বিষয় পরীক্ষা করুন:

1. প্রোগ্রামটি শুধু `127.0.0.1`-এ নয়, `0.0.0.0` অথবা `[::]`-এ listen করছে।
2. সার্ভারের firewall port-টির অনুমতি দিচ্ছে। দেখুন [Firewall](firewall.md)।
3. আপনার hosting provider-এর firewall-ও (অনেক সময় এর নাম "security group" বা "cloud firewall") port-টির অনুমতি দিচ্ছে।

## Firewall চালু করার আগে

প্রথমে রিপোর্টটি চালান এবং বাইরে থেকে যেসব port-এ পৌঁছানো যেতেই হবে সেগুলো টুকে রাখুন। এরপর ঠিক সেই port-গুলোই [firewall-setup](scripts/firewall-setup.md)-কে দিন। এতে সবচেয়ে প্রচলিত ভুলটি এড়ানো যায়: firewall চালু করে এমন একটি সার্ভিস বন্ধ করে ফেলা, যার কথা মনে ছিল না।

## ready-fast যা করে না

নেটওয়ার্ক কনফিগারেশন বদলায় এমন কোনো স্ক্রিপ্ট ready-fast-এ নেই। এটি static IP address বসায় না, DNS server বদলায় না, VPN সংযোগ তৈরি করে না এবং kernel-এর network parameter-ও ঠিক করে না। Ubuntu-তে নেটওয়ার্ক কনফিগার করা হয় `/etc/netplan/`-এ, Debian-এ সাধারণত `/etc/network/interfaces`-এ; এ ধরনের পরিবর্তনের জন্য আপনার ডিস্ট্রিবিউশন বা provider-এর ডকুমেন্টেশন অনুসরণ করুন।

## আরও সাহায্য

স্ক্রিপ্টটির সমস্যা ও error বার্তাগুলোর তালিকা আছে [network-info](scripts/network-info.md) পাতায়। সাধারণ সাহায্য পাবেন [সমস্যা সমাধান](troubleshooting.md) পাতায়।
