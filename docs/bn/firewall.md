# Firewall

🌐 [English](../en/firewall.md) | **বাংলা**

[← ডকুমেন্টেশনের মূল পাতা](README.md)

Firewall হলো নেটওয়ার্ক সংযোগের দারোয়ান। ইন্টারনেট থেকে আসা কোন কোন সংযোগ আপনার সার্ভারের প্রোগ্রামগুলো পর্যন্ত পৌঁছাতে পারবে, তা এটিই ঠিক করে। Firewall না থাকলে কোনো port-এ listen করছে এমন প্রতিটি প্রোগ্রামের সাথে যে কেউ যোগাযোগ করতে পারে।

ready-fast ব্যবহার করে UFW (Uncomplicated Firewall); এটি Ubuntu ও Debian-এর প্রচলিত firewall টুল। এই গাইডে প্রচলিত কয়েকটি সেটআপ এবং পরে rule কীভাবে পরিচালনা করবেন তা দেখানো হয়েছে। স্ক্রিপ্টটি ঠিক কীভাবে কাজ করে, তা লেখা আছে [firewall-setup](scripts/firewall-setup.md) পাতায়।

## মূল ধারণা

ready-fast যে সেটআপ তৈরি করে, তা একটি সহজ নিয়ম মেনে চলে:

- **বাইরে থেকে আসা** সংযোগ বন্ধ থাকে; শুধু আপনি যেসব port-এর অনুমতি দেন সেগুলো ছাড়া।
- **বাইরে যাওয়া** সংযোগ, অর্থাৎ যেগুলো সার্ভার নিজে শুরু করে, সবই খোলা থাকে।

তাই আপনাকে শুধু একটি প্রশ্নের উত্তর দিতে হবে: বাইরে থেকে কোন কোন port-এ পৌঁছানো যেতে হবে? নিশ্চিত না হলে আগে listening port-এর তালিকাটি দেখে নিন; বিস্তারিত [নেটওয়ার্কিং](networking.md) গাইডে আছে।

## Firewall সেটআপ করুন

সবসময় আগে preview দেখে নিন:

```bash
sudo ready-fast run firewall-setup --dry-run
```

- Root permission: লাগবে।
- ঝুঁকি: preview-তে দেখানো SSH port ভুল হলে আপনি নিজেকে সার্ভারের বাইরে আটকে ফেলতে পারেন। `3. Allow incoming` দিয়ে শুরু হওয়া লাইনটি মনোযোগ দিয়ে পড়ুন। নতুন একটি লগইন পরীক্ষা না করা পর্যন্ত আপনার SSH সেশনটি খোলা রাখুন।

এরপর আপনার সার্ভারের সাথে যে কমান্ডটি মেলে সেটি বেছে নিন:

| পরিস্থিতি | কমান্ড |
| --- | --- |
| শুধু SSH-এ পৌঁছানো যাবে | `sudo ready-fast run firewall-setup` |
| Web server (HTTP ও HTTPS) | `sudo ready-fast run firewall-setup --web` |
| SSH চলছে port 2222-এ | `sudo ready-fast run firewall-setup --ssh-port 2222` |
| Web server ও WireGuard VPN | `sudo ready-fast run firewall-setup --web --allow 51820/udp` |
| TCP port 8080-এ একটি application | `sudo ready-fast run firewall-setup --allow 8080/tcp` |

পরে অন্য অপশন দিয়ে স্ক্রিপ্টটি আবারও চালাতে পারেন। এটি নতুন rule-গুলো যোগ করে এবং আগেরগুলো রেখে দেয়।

## Firewall-এর অবস্থা দেখুন

```bash
sudo ufw status verbose
```

`Status: active` মানে firewall চালু আছে। `Default:` লাইনটি মূল নীতি দেখায়, আর তার নিচের টেবিলে অনুমতি দেওয়া প্রতিটি port-এর তালিকা থাকে।

Rule-গুলো নম্বরসহ দেখতে (কোনো একটি rule মুছতে চাইলে এটি কাজে লাগে):

```bash
sudo ufw status numbered
```

## হাতে rule বদলানো

প্রথমবার সেটআপের পর আপনি সরাসরি `ufw` দিয়েই rule পরিচালনা করতে পারেন। এই কমান্ডগুলোর সবগুলোর জন্য root লাগে।

আরও একটি port-এর অনুমতি দিন:

```bash
sudo ufw allow 8080/tcp
```

সেই rule-টি আবার সরিয়ে দিন:

```bash
sudo ufw delete allow 8080/tcp
```

শুধু একটি নির্দিষ্ট IP address থেকে SSH-এর অনুমতি দিন (এখানে `203.0.113.50`):

```bash
sudo ufw allow from 203.0.113.50 to any port 22 proto tcp
```

**এই rule-টি নিয়ে সাবধান থাকুন।** এটি তখনই কাজে আসে, যখন আপনি port 22-এর সাধারণ rule-টিও মুছে ফেলেন; আর তখন শুধু ওই একটি address থেকেই লগইন করা যায়। বাসাবাড়ির ও মোবাইল ইন্টারনেটের অনেক সংযোগেই IP address নিয়মিত বদলে যায়। আপনার address বদলে গেলে আপনি সার্ভারের বাইরে আটকে পড়বেন। আপনার fixed IP address অথবা ঢোকার দ্বিতীয় কোনো পথ থাকলে তবেই এটি ব্যবহার করুন।

SSH-এ বারবার লগইনের চেষ্টা ধীর করে দিন:

```bash
sudo ufw limit 22/tcp
```

কোনো address অল্প সময়ের মধ্যে খুব বেশি সংযোগ খুললে এই rule সেটিকে কিছু সময়ের জন্য আটকে দেয়।

## Docker ও UFW

**Docker container যে port প্রকাশ করে, UFW তা সুরক্ষিত রাখে না।** Docker নিজের firewall rule নিজে লেখে, এবং সেগুলো UFW-এর rule-এর আগে যাচাই হয়। `-p 8080:80` দিয়ে চালু করা container-এ ইন্টারনেট থেকে পৌঁছানো যায়, যদিও `sudo ufw status`-এ port 8080 দেখা যায় না।

নিরাপদ থাকার উপায়:

- গোপন রাখতে চান এমন সার্ভিস শুধু local address-এ প্রকাশ করুন: `-p 127.0.0.1:8080:80`।
- যা সত্যিই সবার জন্য উন্মুক্ত থাকা দরকার, শুধু তা-ই সব address-এ প্রকাশ করুন।
- `sudo ready-fast run network-info` দিয়ে ফলাফল মিলিয়ে দেখুন।

আরও জানতে [Docker](docker.md) গাইডটি দেখুন।

## আপনার hosting provider-এর firewall

অনেক provider-এর নিজস্ব firewall থাকে, যা আপনার সার্ভারের সামনে বসে; এর নাম প্রায়ই "security group" বা "cloud firewall"। এটি UFW থেকে আলাদাভাবে কাজ করে। একটি সংযোগকে **দুটি** firewall-এরই অনুমতি পেতে হয়। কোনো port UFW-তে খোলা থাকার পরও সেখানে পৌঁছানো না গেলে আপনার provider-এর control panel দেখুন।

## Firewall বন্ধ করা

```bash
sudo ufw disable
```

এতে filtering সঙ্গে সঙ্গে বন্ধ হয়ে যায়; আপনার rule-গুলো থেকে যায় এবং `sudo ufw enable` দিলে আবার কার্যকর হয়। সব rule মুছে ফেলার নিয়মসহ আগের অবস্থায় ফিরে যাওয়ার পূর্ণাঙ্গ নির্দেশনা আছে [firewall-setup](scripts/firewall-setup.md) পাতায়।

## এই সেটআপ যা করে না

- এটি বাইরে যাওয়া সংযোগ সীমিত করে না।
- এটি সংযোগের ভেতরের বিষয়বস্তু পরীক্ষা করে না এবং আক্রমণ শনাক্ত করে না।
- এটি Docker-এর প্রকাশ করা port সুরক্ষিত রাখে না (ওপরে দেখুন)।
- এটি সফটওয়্যার হালনাগাদ রাখার বিকল্প নয়।

## আরও সাহায্য

Error বার্তা ও সমাধান আছে [firewall-setup](scripts/firewall-setup.md) পাতার সমস্যা সমাধান অংশে। সার্ভারের বাইরে আটকে পড়লে [সমস্যা সমাধান](troubleshooting.md) পাতাটি দেখুন।
