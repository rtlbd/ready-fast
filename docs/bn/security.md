# নিরাপত্তা

🌐 [English](../en/security.md) | **বাংলা**

[← ডকুমেন্টেশনের মূল পাতা](README.md)

এই পাতায় ব্যাখ্যা করা হয়েছে ready-fast কীভাবে নিরাপদ থাকার কথা মাথায় রেখে তৈরি, এটি কোথায় কোথায় সংযোগ করে এবং নতুন একটি সার্ভার ধাপে ধাপে কীভাবে সুরক্ষিত করবেন। ready-fast কী কী করে না, সেটাও এখানে খোলাখুলি বলা আছে।

## ready-fast আপনাকে কীভাবে সুরক্ষা দেয়

- **সবকিছুই আপনি পড়ে দেখতে পারেন।** পুরো toolkit-টি সাধারণ shell script। কিছুই compile করা বা লুকানো নেই, আর ইন্টারনেট থেকে সরাসরি code চালিয়ে দেয় এমন কোনো installer-ও নেই।
- **Preview মোড।** কোনো কিছু বদলায় এমন প্রতিটি স্ক্রিপ্ট `--dry-run` গ্রহণ করে; তখন সেটি কী করত শুধু তা-ই দেখায়।
- **নিশ্চিতকরণ।** সিস্টেমের সেটিং বদলায় বা ফাইল overwrite করে এমন স্ক্রিপ্টগুলো একটি সারসংক্ষেপ দেখিয়ে আপনার উত্তরের অপেক্ষা করে। টার্মিনাল না থাকলে `--yes` না দেওয়া পর্যন্ত এগুলো থেমে থাকে।
- **অপারেটিং সিস্টেম যাচাই।** সফটওয়্যার ইনস্টল করে বা সিস্টেমের সেটিং বদলায় এমন স্ক্রিপ্টগুলো যে সিস্টেমের জন্য লেখা হয়নি, সেখানে থেমে যায়।
- **আটকে পড়া থেকে সুরক্ষা।** যেসব সেটিং দিলে আর কেউই লগইন করতে পারবে না, `ssh-hardening` সেগুলো প্রত্যাখ্যান করে; আর `firewall-setup` firewall চালু করার আগে সবসময় SSH port-এর জন্য একটি rule যোগ করে নেয়।
- **ব্যবহারের আগে কনফিগারেশন পরীক্ষা।** `ssh-hardening` `sshd -t` চালায় এবং পরীক্ষা ব্যর্থ হলে নিজের পরিবর্তন নিজে থেকেই বাতিল করে দেয়।
- **ফেরার পথ।** প্রতিটি স্ক্রিপ্টের পাতায় আগের অবস্থায় ফিরে যাওয়ার নির্দেশনা আছে। কোনো স্ক্রিপ্ট যে ফাইল বদলায়, তার একটি কপি আগে `/var/backups/ready-fast`-এ রেখে দেয়।
- **কোনো নজরদারি নেই।** ready-fast ব্যবহারের কোনো তথ্য সংগ্রহ করে না এবং আপনার সার্ভার সম্পর্কে এর নির্মাতাদের কাছে কিছুই পাঠায় না।

## ইন্টারনেট সংযোগ

| গন্তব্য | কখন | কেন |
| --- | --- | --- |
| আপনার apt mirror | `docker-install`-এ, এবং `ufw` না থাকলে `firewall-setup`-এ | প্যাকেজ ইনস্টল করার জন্য। |
| `download.docker.com` | `docker-install`-এ | Docker-এর signing key ও প্যাকেজের জন্য। |
| `api.ipify.org` | `network-info`-তে, শুধু `--public-ip` দিলে | Public IP address জানার জন্য। এই সার্ভিসটি আপনার সার্ভারের IP address দেখতে পায়। |
| `example.com` | `network-info`-তে, শুধু `--check` দিলে | DNS ও বাইরের দিকে HTTPS সংযোগ পরীক্ষার জন্য। |

বাকি স্ক্রিপ্টগুলো কোনো নেটওয়ার্ক সংযোগ তৈরি করে না।

## Root permission

তিনটি স্ক্রিপ্টের জন্য সবসময় root লাগে: `docker-install`, `firewall-setup` ও `ssh-hardening`। ব্যাকআপের স্ক্রিপ্টগুলোর জন্য root লাগে শুধু তখনই, যখন ফাইলগুলোর কারণে তা দরকার হয়; আর রিপোর্ট দেখানোর স্ক্রিপ্ট দুটির জন্য কখনোই লাগে না। প্রতিটি স্ক্রিপ্টের পাতার "যা যা প্রয়োজন" অংশে বিষয়টি লেখা আছে।

ভালো অভ্যাস হলো সারাক্ষণ `root` হিসেবে কাজ না করে সাধারণ ব্যবহারকারী হিসেবে লগইন করা এবং root দরকার হলে কমান্ডের আগে `sudo` বসানো। সাধারণ ব্যবহারকারী হিসেবে ভুল করলে ক্ষতি সাধারণত অনেক কম হয়।

## নতুন সার্ভারের চেকলিস্ট

ধাপগুলো ক্রম অনুযায়ী অনুসরণ করুন। এখানে `deploy` একটি উদাহরণ user name এবং `203.0.113.10` একটি উদাহরণ সার্ভার-ঠিকানা; এগুলোর জায়গায় নিজের তথ্য বসান।

**1. সিস্টেম আপডেট করুন।** সার্ভারে চালান:

```bash
sudo apt-get update
sudo apt-get upgrade
```

প্রথম লাইনটি প্যাকেজের তালিকা হালনাগাদ করে; দ্বিতীয় লাইনটি পাওয়া যায় এমন আপডেটগুলো ইনস্টল করে এবং শুরু করার আগে জিজ্ঞেস করে নেয়।

**2. Administrator-এর ক্ষমতাসহ একজন সাধারণ ব্যবহারকারী তৈরি করুন।** সার্ভারে চালান:

```bash
sudo adduser deploy
sudo usermod -aG sudo deploy
```

প্রথম লাইনটি ব্যবহারকারী তৈরি করে এবং একটি পাসওয়ার্ড চায়। দ্বিতীয় লাইনটি ব্যবহারকারীকে `sudo` গ্রুপে যোগ করে।

**3. SSH key তৈরি করুন।** এটি সার্ভারে নয়, আপনার নিজের কম্পিউটারে চালান:

```bash
ssh-keygen -t ed25519
ssh-copy-id deploy@203.0.113.10
```

প্রথম লাইনটি একজোড়া key তৈরি করে (প্রস্তাবিত ফাইলের নাম মেনে নিতে Enter চাপুন এবং একটি passphrase ঠিক করুন)। দ্বিতীয় লাইনটি public key-টি সার্ভারে কপি করে।

**4. Key দিয়ে লগইন পরীক্ষা করুন।** আপনার নিজের কম্পিউটারে নতুন একটি টার্মিনাল খুলুন:

```bash
ssh deploy@203.0.113.10
```

সার্ভারের পাসওয়ার্ড না চেয়েই আপনার ঢুকে যাওয়ার কথা। এই ব্যবহারকারীর জন্য `sudo -v` কাজ করছে কি না, সেটাও দেখে নিন। দুটিই কাজ না করা পর্যন্ত সামনে এগোবেন না।

**5. মূল কনফিগারেশন সংরক্ষণ করুন।**

```bash
sudo ready-fast run backup-create --source /etc --name etc-original
```

**6. SSH শক্ত করুন।** এতে root লগইন ও পাসওয়ার্ড দিয়ে লগইন বন্ধ হয়ে যায়:

```bash
sudo ready-fast run ssh-hardening --root-login no --disable-password-auth
```

আপনার সেশনটি খোলা রাখুন এবং অন্য একটি টার্মিনাল থেকে নতুন লগইন পরীক্ষা করুন। বিস্তারিত: [ssh-hardening](scripts/ssh-hardening.md)।

**7. Firewall চালু করুন।** Web server হলে `--web` যোগ করুন:

```bash
sudo ready-fast run firewall-setup
```

বিস্তারিত: [firewall-setup](scripts/firewall-setup.md)।

**8. নজর রাখতে থাকুন।** সার্ভার নিয়মিত পরীক্ষা করুন এবং আপডেট ইনস্টল করুন:

```bash
ready-fast run system-monitor
```

বিস্তারিত: [মনিটরিং](monitoring.md) ও [ব্যাকআপ](backup.md)।

## যে সতর্কতাগুলো জেনে রাখা দরকার

- **`docker` গ্রুপ মানেই root।** যে `docker` চালাতে পারে, সে পুরো সার্ভারের নিয়ন্ত্রণ নিয়ে নিতে পারে। শুধু বিশ্বস্ত ব্যবহারকারীদেরই যোগ করুন।
- **Docker-এর port UFW-কে পাশ কাটায়।** `-p 8080:80` দিয়ে প্রকাশ করা container port firewall-এর তালিকায় না থাকলেও ইন্টারনেটের জন্য খোলা থাকে। গোপন রাখতে চান এমন সার্ভিসের জন্য `-p 127.0.0.1:8080:80` ব্যবহার করুন। বিস্তারিত: [Firewall](firewall.md)।
- **ব্যাকআপ এনক্রিপ্ট করা থাকে না।** Source ডিরেক্টরিতে যা কিছু ছিল, গোপন তথ্যসহ তার সবই archive-এ থাকে। প্রতিটি কপি সুরক্ষিত রাখুন। বিস্তারিত: [ব্যাকআপ](backup.md)।
- **SSH ও firewall-এর পরিবর্তনে আপনি সার্ভারের বাইরে আটকে পড়তে পারেন।** সবসময় একটি সেশন খোলা রাখুন এবং hosting provider-এর web console-এ কীভাবে ঢুকতে হয় তা জেনে রাখুন।

## ready-fast যা করে না

ready-fast একটি সার্ভারকে মজবুত প্রাথমিক সেটআপ দেয়। এটি পূর্ণাঙ্গ কোনো নিরাপত্তা-পণ্য নয়:

- এটি intrusion detection, malware scanner কিংবা আক্রমণকারীকে নিজে থেকে ban করে এমন টুল ইনস্টল করে না।
- এটি স্বয়ংক্রিয় security update কনফিগার করে না।
- এটি kernel parameter, ফাইলের permission বা পাসওয়ার্ডের নীতিমালা বদলায় না।
- এটি আপনার application, container বা ওয়েবসাইটে কোনো দুর্বলতা আছে কি না তা পরীক্ষা করে না।
- এটি কোনো সার্ভারকে কোনো security standard-এর শর্ত পূরণকারী বানিয়ে দেয় না।

নিরাপত্তা একটি চলমান কাজ: আপডেট ইনস্টল করুন, কার কার প্রবেশাধিকার আছে তা মাঝে মাঝে যাচাই করুন এবং ব্যাকআপ পরীক্ষা করে দেখুন।

## ready-fast-এর কোনো নিরাপত্তা-সমস্যা জানানো

ready-fast-এর নিজের মধ্যে কোনো দুর্বলতা খুঁজে পেলে অনুগ্রহ করে শুরুতেই পাবলিক issue-তে তার বিস্তারিত প্রকাশ করবেন না। `https://github.com/rtlbd`-এ থাকা GitHub profile-এর মাধ্যমে maintainer-দের সাথে ব্যক্তিগতভাবে যোগাযোগ করুন এবং সমাধানের জন্য সময় দিন। সাধারণ bug কীভাবে জানাবেন তা [সমস্যা সমাধান](troubleshooting.md) পাতায় বলা আছে।
